# Trigu API v1

API отдаёт **поставки в работе** (по умолчанию — статусы «Формируется» и «В производстве», Wildberries и OZON; конкретную поставку по номеру — в любом статусе) и **товары в этих поставках**. Только чтение — через API ничего изменить нельзя. Данные — те же, что в «Ленте поставок».

Формат — JSON (UTF-8). Время — московское (UTC+3), ISO-8601: `2026-11-24T15:02:16+03:00`.

## Авторизация

Ключ выпускается в «Настройки → Интеграция» (доступно базовому администратору). Он показывается один раз — сохраните его. Передавайте ключ в заголовке каждого запроса:

```
Authorization: Bearer trg_0123456789abcdef0123456789abcdef01234567
```

Допустим и альтернативный заголовок `X-Api-Key: trg_…`. Ключ в адресной строке не принимается (он попадает в журналы серверов).

> **Храните ключ как пароль.** Он даёт чтение данных вашей организации. Если ключ попал не туда — отзовите его в настройках и выпустите новый: старый перестанет работать сразу.

## Лимиты

**120 запросов в минуту** на ключ. При превышении сервер отвечает `429` с заголовком `Retry-After` (секунд до следующего окна). Список поставок считается на лету — не опрашивайте чаще, чем раз в 1–2 минуты.

## GET https://wbpar.ru/users/api/v1/supplies.php

Один адрес, два режима. Первый — **список поставок** (постранично, при желании сразу с товарами); его можно сузить фильтрами — по **номеру поставки** (`number`), площадке (`marketplace`) и статусу (`status`). Фильтр действует, только если параметр указан. **Без номера** отдаются только поставки «Формируется» и «В производстве»; **если номер указан — поставка находится независимо от её статуса** (в пределах последних ~60 дней, как в «Ленте поставок»). Второй режим — **товары одной поставки** (постранично), когда указан параметр `supply`. Если в поставках много товаров — берите список без товаров и забирайте товары каждой поставки отдельными запросами: так ответы остаются небольшими.

| Параметр | Режим | Описание |
|---|---|---|
| `supply` | товары | Номер поставки (`WB-GI-319846892` или `OZ-WH-0029402`). Есть — отдаются товары этой поставки, в любом её статусе. |
| `number` | список | Фильтр по номеру поставки. Можно несколько через запятую (до 50): `?number=WB-GI-319846892,OZ-WH-0029402`. Регистр не важен. **Ищет по всем статусам** (без номера в списке только «Формируется»/«В производстве»). Ответ — тот же список; вместе с `include=items` сразу с товарами. Если такой поставки нет среди доступных — пустой `data`. |
| `marketplace` | список | `wb` или `ozon`. По умолчанию обе площадки. |
| `status` | список | `forming` (Формируется) или `production` (В производстве). По умолчанию оба. |
| `include` | список | `items` — вложить товары в каждую поставку (до 100 товаров на поставку, см. `items_truncated`). |
| `page` | оба | Номер страницы, с 1. По умолчанию 1. |
| `limit` | оба | Размер страницы. Список: по умолчанию 50, максимум 200 (с `include=items`: по умолчанию 10, максимум 25). Товары поставки: по умолчанию 100, максимум 500. |

## Список поставок

```bash
curl -H "Authorization: Bearer trg_…" \
  "https://wbpar.ru/users/api/v1/supplies.php?marketplace=wb&limit=2"
```

```json
{
  "data": [
    {
      "number": "WB-GI-319847234",
      "name": "Настя вечер Кепки 24.11",
      "shop": "Бренд Рекспринт",
      "marketplace": "wb",
      "status": "forming",
      "status_label": "Формируется",
      "created_at": "2026-11-24T15:02:16+03:00",
      "items_count": 1,
      "items_url": "/users/api/v1/supplies.php?supply=WB-GI-319847234"
    }
  ],
  "pagination": { "page": 1, "limit": 2, "total": 81, "pages": 41, "has_more": true },
  "generated_at": "2026-11-24T15:02:53+03:00"
}
```

| Поле | Описание |
|---|---|
| `number` | Номер поставки: WB — `WB-GI-…`, OZON — `OZ-WH-…`. Уникален, по нему запрашиваются товары. |
| `name` | Название поставки. |
| `shop` | Название магазина. |
| `marketplace` | Площадка: `wb` или `ozon`. |
| `status` | Статус: `forming` — формируется, `production` — в производстве. У поставок, найденных по `number`, возможны и другие: `deliversc` — доставка в СЦ, `sorting` — сортируется, `ready` — готова к отгрузке, `delivery` — в доставке, `dogruzka` — возможно догрузка, `done` — завершена. |
| `status_label` | Статус словами («Формируется» / «В производстве»). |
| `created_at` | Когда создана поставка. |
| `items_count` | Число позиций. В списке — ориентир (может включать отменённые); точное значение — в режиме `supply=`. |
| `items_url` | Адрес для получения товаров этой поставки. |

Новые поставки идут сверху (по дате создания). Страницы берутся «снимком» на момент запроса: если между запросами создалась поставка, граница страниц сдвинется — при обходе ориентируйтесь на `number`, а не на позицию.

## Фильтр по номеру поставки

Чтобы получить конкретные поставки (с товарами или без), укажите их номера в `number`. Формат ответа тот же, что у списка:

```bash
curl -H "Authorization: Bearer trg_…" \
  "https://wbpar.ru/users/api/v1/supplies.php?number=WB-GI-319846892,OZ-WH-0029402&include=items"
```

Фильтры можно сочетать: `?number=…&status=production`. Номер ищется **независимо от статуса поставки** — в том числе у поставок, которые уже в доставке или завершены (поле `status` покажет их реальный статус). Номер, которого нет среди доступных ключу поставок, в ответ не попадает — если не найдено ничего, `data` будет пустым массивом (это не ошибка). Без `number` список содержит только «Формируется» и «В производстве».

## Товары поставки

```bash
curl -H "Authorization: Bearer trg_…" \
  "https://wbpar.ru/users/api/v1/supplies.php?supply=WB-GI-319841767&limit=100&page=1"
```

```json
{
  "data": {
    "number": "WB-GI-319841767",
    "name": "Футболки вечер 24.11",
    "shop": "Бренд Рекспринт",
    "marketplace": "wb",
    "status": "production",
    "status_label": "В производстве",
    "created_at": "2026-11-24T12:10:04+03:00",
    "items_count": 2,
    "items": [
      {
        "id": "6345288271",
        "name": "Футболка мужская оверсайз с принтом профессия Тренер",
        "category": "Футболки",
        "size": "S",
        "size_ru": "44-46",
        "color": "черный",
        "article": "t150/черный",
        "article_full": "t150/черный",
        "quantity": 1
      }
    ]
  },
  "pagination": { "page": 1, "limit": 100, "total": 2, "pages": 1, "has_more": false }
}
```

| Поле товара | Описание |
|---|---|
| `id` | Идентификатор позиции: WB — номер заказа (сборочного задания), OZON — номер отправления. |
| `name` | Название товара. Если в артикуле есть пометка принта (`-СПИНА`, `-ГРУДЬ` и т. п.), в конце добавляется « - принт на спине» и т. д. — как в интерфейсе. |
| `category` | Категория товара на площадке («Футболки», «Кружки», …). |
| `size` | Размер (`S`, `XL`, `2XL`…). Пустая строка — у безразмерных товаров. |
| `size_ru` | Российский размер (`44-46`, `50`). Пустая строка, если не указан. |
| `color` | Цвет. Пустая строка, если не указан. |
| `article` | Артикул продавца в том виде, как он показан в интерфейсе (у OZON — без размера на конце). |
| `article_full` | Полный артикул продавца как в кабинете площадки (у OZON — вместе с размером, например `600136-7-XS`; у WB совпадает с `article`). |
| `quantity` | Количество единиц в позиции (у WB всегда 1). |

Отменённые позиции в выдачу не попадают. Если площадка отдаёт отправление с несколькими товарами, каждая строка отправления — отдельный элемент с тем же `id`.

## Список сразу с товарами

Для небольших объёмов можно вложить товары в список одним запросом: `?include=items`. В каждой поставке — не более 100 товаров; если их больше, `items_truncated` будет `true`, остальное забирайте по `items_url`.

```bash
curl -H "Authorization: Bearer trg_…" \
  "https://wbpar.ru/users/api/v1/supplies.php?include=items&limit=10"
```

## Постраничный обход

Увеличивайте `page`, пока `pagination.has_more` равно `true`:

```python
import requests

URL = "https://wbpar.ru/users/api/v1/supplies.php"
HEAD = {"Authorization": "Bearer trg_…"}

page = 1
while True:
    r = requests.get(URL, headers=HEAD, params={"page": page, "limit": 100}).json()
    for supply in r["data"]:
        items, p = [], 1
        while True:                      # товары поставки — тоже постранично
            d = requests.get(URL, headers=HEAD, params={"supply": supply["number"], "page": p, "limit": 500}).json()
            items += d["data"]["items"]
            if not d["pagination"]["has_more"]:
                break
            p += 1
        print(supply["number"], supply["status"], len(items))
    if not r["pagination"]["has_more"]:
        break
    page += 1
```

## Ошибки

Ошибка приходит с HTTP-кодом и телом вида `{ "error": { "code": "…", "message": "…" } }`.

| HTTP | code | Когда |
|---|---|---|
| 400 | `bad_request` | Недопустимое значение параметра (`status`, `marketplace`, `include`). |
| 401 | `missing_api_key` | Не передан ключ. |
| 401 | `invalid_api_key` | Ключ неверный или отозван. |
| 403 | `forbidden` | У владельца ключа нет доступа к данным производства. |
| 404 | `supply_not_found` | Поставки с таким номером нет среди доступных ключу (или она старше окна данных ~60 дней). |
| 405 | `method_not_allowed` | Используйте только `GET`. |
| 429 | `rate_limit_exceeded` | Превышен лимит 120 запросов в минуту; смотрите `Retry-After`. |
| 500 | `server_error` | Внутренняя ошибка — повторите запрос позже. |
