# RexArticles — описание работы программы

RexArticles — настольное приложение для автоматического подбора и сбора файлов принтов по артикулам из PDF-поставок Wildberries и Ozon. Программа читает поставку, находит нужные файлы в настроенных источниках и создаёт готовую папку с пронумерованными копиями принтов.

## Основной сценарий работы

1. В настройках создайте магазин и настройте для него WB и/или Ozon.
2. Укажите основную папку с принтами или смонтированный сетевой/WebDAV-диск. При необходимости добавьте дополнительные источники.
3. Создайте или обновите индекс принтов.
4. Нажмите «Загрузить»: выберите поставки из Trigu API или локальные PDF-файлы.
5. Проверьте распознанные артикулы и при необходимости внесите ручные уточнения.
6. Нажмите «Запустить». Программа найдёт принты и скопирует их в папку результата.

Если часть принтов не найдена, в папке результата создаётся файл `ненайденные.txt` с порядковым номером, артикулом, размером и отметкой `СПИНА`, если она есть.

## Что программа распознаёт в поставках

### Wildberries

Для WB программа определяет магазин, артикулы, размеры и расположение принта из PDF-поставки. Магазин выбирается по данным поставки и сопоставляется с настройками.

### Ozon

Поддерживаются обычные поставки Ozon и формат задания Ozon с таблицей `Товар`, `Артикул`, `Характеристики`.

- Размер может быть отделён от артикула запятой, дефисом или пробелом.
- В формате задания размер берётся из поля `Характеристики` после `Размер:`.
- Если в названии товара есть слова «спина», «на спине», «сзади» или «принт на спине», к результату добавляется идентификатор `СПИНА`.
- Словарь размеров Ozon находится в отдельной вкладке настроек. Встроенные записи можно дополнять своими; пользовательские размеры начинают применяться со следующей загрузки поставки.

Если размер не удалось определить, артикул сохраняется целиком, а размер получает значение `0`.

### Trigu API

Во вкладке **API** настроек укажите ключ Trigu. В окне «Загрузить поставки» доступны активные поставки WB и Ozon, фильтры по магазину и статусу, а также чекбоксы для надёжного выбора. Порядок площадок (WB → Ozon или Ozon → WB) задаётся в настройках и сохраняется.

Товары поставки Trigu группируются по категориям. Новые категории добавляются в список настроек автоматически; их порядок можно изменить кнопками «Вверх» и «Вниз». Локальные PDF-поставки не меняют свой порядок.

## Поиск и индексы

### Нормализация артикулов

Для внутреннего поиска артикулы приводятся к Unicode NFC, нижнему регистру и виду без пробелов. Поэтому варианты вроде `АРТ 123` и `арт123` найдут один и тот же файл. В таблице, логах и именах файлов отображается исходный, читаемый артикул.

### SQLite-индекс

Сведения о файлах хранятся в SQLite. Индекс содержит нормализованный артикул и путь к файлу, поэтому поиск не требует повторного обхода всей папки.

Для локальных папок программа выполняет инкрементальную проверку: повторно использует неизменившиеся каталоги и добавляет/обновляет только изменившиеся данные. Для сетевых и WebDAV-папок операции чтения сериализуются и при временной ошибке выполняются повторные попытки.

Один и тот же источник принтов индексируется один раз и может использоваться несколькими магазинами. Это особенно полезно, когда несколько профилей обращаются к общей сетевой папке.

## Настройки магазина

Для каждого магазина и каждого типа поставки WB/Ozon доступны независимые параметры:

- основная папка принтов: локальная, сетевая или WebDAV-папка;
- дополнительные источники файлов с настраиваемым порядком;
- matcher — алгоритм сопоставления артикула;
- поиск только PNG;
- диапазоны размеров в именах файлов;
- правила ручного уточнения файлов и, для локальных источников, копирование/переименование при уточнении.

### Matcher

Доступны следующие алгоритмы:

| Matcher | Правило поиска |
| --- | --- |
| `Simple` | точное совпадение артикула; JPG исключаются |
| `Rozenberg` | используется часть артикула до первого дефиса |
| `Alekseev` | дополнительно пробуется вариант без суффикса `Black`/`White` |
| `PdfOnly` | ищутся только PDF-файлы |
| `Kristabell` | поддерживаются имена с диапазонами размеров |

### Диапазоны размеров

Если один файл предназначен для нескольких размеров, в настройках можно задать паттерн из имени файла и список размеров. Например:

```text
Паттерн: (XS_L)
Размеры: XS, S, M, L
```

При поиске подходящий паттерн пробуется раньше обычного артикула. Порядок диапазонов важен: первый найденный файл имеет приоритет.

## Ручные уточнения

### Уточнение артикула

Клик по артикулу в дочерней строке поставки открывает окно уточнения. В нём можно указать фактический артикул вместо распознанного. Правило сохраняется отдельно для конкретной пары «магазин + WB/Ozon» и применяется к повторяющимся строкам текущей и будущих поставок.

### Уточнение файла

Кнопка с лупой у строки позволяет выбрать фактический файл принта. Такая привязка сохраняется для артикула и размера и имеет приоритет над автоматическим подбором. Для одинакового артикула в одной поставке уточнение применяется ко всем соответствующим строкам.

## Результат поиска

Файлы копируются в папку результата с порядковыми номерами в порядке строк поставки. Имя включает артикул, размер и, при необходимости, положение принта. Примеры:

```text
1. ART-001 [M].png
2. ART-002 [XL СПИНА].pdf
```

Ошибки доступа к отдельным файлам не останавливают обработку всей поставки: они фиксируются в журнале, а соответствующие позиции попадают в `ненайденные.txt`.

## Данные программы

Пользовательские данные не должны храниться внутри `.app` и сохраняются при обновлении программы.

- macOS: `~/Library/Application Support/RexArticles`
- Windows: рядом с `RexArticles.exe`; установщик сохраняет эти файлы при обновлении.

Основные пользовательские файлы:

- `stores.json` — магазины и параметры источников;
- `config.json` — общие настройки, тема, ключ Trigu и порядок площадок/категорий;
- `manual_overrides.json` — ручные привязки файлов;
- `article_corrections.json` — ручные уточнения артикулов;
- SQLite-база индексов и журналы работы.

## Логи и диагностика

Кнопка «Логи» открывает журнал операций. В нём можно увидеть ход индексирования, обработанные папки, время операций, повторные попытки сетевых подключений и причины, по которым отдельный файл не был скопирован.
